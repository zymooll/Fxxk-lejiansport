乐健体育 · 目标里程与自动上传版（2026-11-10）

启动
Windows + Python 3.10+。安装 python -m pip install -r requirements.txt。
双击 start.cmd 或运行 python launch.py。地址 http://127.0.0.1:18766。
停止运行 python stop.py。新版入口为 server_v3.py，前端位于 web_v3/。
app.py 与 web/ 保留用于旧版回归测试；正常启动不会运行旧计时/本地记录流程。

使用
1. 添加账号：支持账号密码登录，或导入 {"accessToken":"…","refreshToken":"…"}。
   原 Authorization/Cookie JSON 继续兼容。密码只用于一次登录，不落盘、不输出到日志。
   账号备注可选。同一真实账号再次添加时会更新现有条目。
2. 选择“使用账号”：检查 Token 到期时间，必要时续期，并读取当前本人、学期、规则、累计/日/周公里数。
   验证失败时显示状态，可手动重试。Token 也失效时需重新登录或导入凭据。
3. 设置圈数和偏移参数，点击“生成完整轨迹”。没有计时阶段，也无需先保存本地记录。
   随机种子默认-1，每次取系统安全随机数；填写0–2147483647可在相同设置下复现轨迹。
   账号卡片上的“生成并上传”会检查该账号、读取点击时的全部生成设置，新生成一条轨迹后立即提交。
   连点会在本次操作结束前被忽略；账号检查或生成失败不会上传页面上的旧轨迹。
4. “上传本次轨迹”只提交当前账号绑定的本次生成结果。切换账号会清除页面中的旧轨迹。
   结束时间取提交时刻，开始时间按计划时长回推。原有签名构造与服务器判定分离。
   服务器返回记录ID后会回查有效里程/无效原因；收到回执不等于取得有效成绩。
5. 删除账号可用“撤销删除”恢复。删除立即使对应会话与未提交轨迹失效。

目标里程与自动上传
每个账号默认跟随服务器的学期目标（semesterMileage）；可独立修改后点击“保存目标”。
“恢复学期目标”清除自定值，后续跟随最新学期规则；目标可设为0，此账号会被视为已达标。
修改中的目标须先保存或恢复，才能预览或批量上传。
账号池底部的“预览上传计划”只刷新凭据、里程和规则并计算计划，不生成或上传轨迹。
“自动一键上传”依次处理账号，每批每个未达标账号最多新生成并提交一条记录。
本次额度取今日剩余额度、本周剩余额度和单次最高里程中的最小值。
圈数=ceil(本次额度km×1000÷实际参考圈长m)。当前参考圈长约433.6m，5km对应12圈；400m跑道则为13圈。
自动圈数覆盖页面手动圈数，其余偏移、相关时间和种子沿用点击时的生成设置；种子-1每次独立随机。
目标仅决定是否继续处理：即使距离目标只剩0.5km，仍按本次可用最高额度生成。
已达目标、额度用满、缺少目标/里程/额度、计划不在开放时段，或今日上传结果待核对时跳过并显示原因。
某账号失败不会中止后续账号；服务器接收回执与有效成绩分别展示，向上取整不保证取得有效成绩。
可点击“停止后续”，当前请求结束后停止剩余账号。关闭页面或响应丢失后，不会自动重发上传。
重新打开可点击“继续未完成批次”，仅处理尚未处理的账号；服务重启会暂停未结束批次，需手动继续。
批次状态与回执保存在本机，不保存轨迹坐标。存在未结束批次时，先继续或停止该批次，再进行手动上传。

随机性与暂存
种子-1（默认）使用 secrets.SystemRandom，由操作系统安全随机源供给随机数；非负整数使用对应的可复现伪随机序列。
这使用 Windows 系统 CSPRNG，不宣称程序直接访问某一硬件真随机设备。
生成结果仅保存在服务进程内，30分钟失效或重启后消失；可自行导出 JSON。
新流程不创建跑步记录表，不提供本地记录列表、保存或计时接口。
内部只持久化必要上传回执及状态，保护已接收或结果不确定的请求不被再次发送；不存轨迹坐标。

凭据保护
账号池凭据位于 .local/accounts/<本机账号ID>/credentials.dpapi，用当前 Windows 用户的 DPAPI 加密。
刷新前后分别创建可验证解密的加密检查点，双 Token 和到期时间一起原子保存。
固定 HTTPS 上游为 https://cpes.legym.cn，校验证书，禁止重定向。
刷新GET只把URL编码后的Refresh Token放入查询参数，不携带旧Authorization或请求体。
同一凭据刷新失败不循环尝试；上传写请求不会自动重发。
当前标签页仅记录本机账号ID用于会话恢复，不在浏览器存储 Token 或密码。
本机账号的旧凭据 JSON 及旧 runs.sqlite3 保留供迁移/恢复，不是新版运行的账号池。
删除账号采用本机可恢复的移除标记，不调用远端注销或删除远端数据。

验证范围
密码登录协议模块位于 login_protocol.py；仓库不包含原始抓包或个人登录资料。
请求构造、响应解包与密码登录网络调用通过模拟响应测试；此前报告的两轮抓包离线核验仍适用。
电脑新发起密码登录是否被当前远端接受，须在页面输入账号密码后完成在线验证；不会读取历史密码代替输入。
账号池真实验收使用现有本机 Token 与只读里程/计划预览接口。直接及批量上传由隔离模拟上游验证，不额外提交真实运动记录。

公开仓库的数据处理
fixtures/ 仅含数学生成的示例路线和区域，不包含真实校园区域或个人运动坐标。
如需使用自己的参考路线，在本机 .local/reference.json 放入151个首尾闭合的经纬度点；可在 .local/region.json 配置本地区域。
运行时优先读取当前数据目录中的私有配置；真实账号的可跑区域仍以服务端读取结果为准。
请在连接真实账号上传前确认已配置自己的路线，示例坐标不代表实际可跑位置。
